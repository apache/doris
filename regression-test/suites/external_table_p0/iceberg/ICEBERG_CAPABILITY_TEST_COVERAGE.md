# Iceberg capability and test coverage inventory

This inventory maps the [published capability matrix](https://doris.apache.org/docs/dev/lakehouse/best-practices/doris-iceberg-capability-matrix/)
and [catalog guide](https://doris.apache.org/docs/dev/lakehouse/catalogs/iceberg-catalog/)
to tests in this repository. Test presence does not imply that every backend, format, version,
scanner, and deployment combination has been executed.

## Scope

- Iceberg format V1/V2/V3, the bundled Iceberg SDK version, and Doris release versions are separate dimensions.
- Iceberg has no Doris Duplicate/Unique/Aggregate target model. Those are INSERT SELECT source
  models; see `write/test_iceberg_write_source_models.groovy`. Iceberg target dimensions include
  format version, partition/sort specs, delete mode, data format, and branch.
- A recording fake checks routing and errors; it does not validate a live catalog or filesystem.
- `Y`/`N` below transcribe the published matrix in REST/HMS/Hadoop/Glue/DLF/S3 Tables/JDBC order.
  They are documentation input, not new executable promises. Current implementation takes precedence.
- The published matrix lags code for table-property mutation and `remove_orphan_files`, which
  have implementation and tests despite all-N rows. The catalog guide's backend summary differs
  from the detailed matrix too. Documentation reconciliation remains necessary.

## Oracle gaps addressed

Existing branch/tag retention suites expire newly created snapshots with a cutoff in 2020.
Those snapshots are not expiration candidates, so preserved refs alone cannot prove protection.
`test_iceberg_ref_retention_expiration_control.groovy` adds a future cutoff, `retain_last=1`,
and an unreferenced snapshot that must disappear while protected main/branch/tag snapshots stay readable.
The equivalent unit uses real in-memory Iceberg metadata.

New transaction tests verify published file sets and historical snapshot contents, rather than
only API calls. They cover multi-partition dynamic overwrite, static overwrite on a branch,
concurrent main/branch append, and atomic publication of update data plus delete files.

Known-bug reproductions retain correct assertions and are individually disabled with a reason.
A skipped test is not passing coverage. Enable them when validating a fix by adding
`-Djunit.jupiter.conditions.deactivate=org.junit.*DisabledCondition` to the Maven test command.

## Execution boundaries

Added FE tests use actual Iceberg metadata operations and recording connector contexts.
The Groovy suites use existing REST/MinIO/Spark fixtures with metamorphic and cross-engine
comparisons, so they do not require handwritten golden results. SQL product execution needs
the managed test environment. Offline unit success and Groovy compilation do not imply SQL
execution, BE unit success, a release compatibility matrix, or full backend coverage.
Actual commands and results belong in the PR validation section.
