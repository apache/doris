# 新集群内置账号的安全初始化

实现基线：`74bcd1aa1735`。该基线的 `skip_localhost_auth_check` 已默认关闭。

## 目标与范围

新初始化的集群默认限制空密码 root/admin 的客户端访问。已有集群继续使用原有
认证策略。配置文件中的显式测试开关可以恢复空密码访问。

范围包括 FE 的 MySQL、HTTP、Stream Load、Thrift 转发认证、Arrow Flight 认证，
以及使用这些入口的部署脚本和回归测试。BE 的执行代码、Thrift 和 Protobuf 定义不变。

## 新老集群判定与持久化

策略标记是集群认证元数据的一部分，存放在 `UserManager` 的可选 Gson 字段中。
缺失字段表示旧策略，不能根据构造函数创建的 root/admin 推断集群是否为新集群。

第一个 FE 的 `OP_ADD_FIRST_FRONTEND` 记录同时携带安全初始化标记。集群成员身份和
认证策略由同一条日志提交；回放时，先应用策略标记，再执行原有成员回放逻辑。
即使成员已经存在，也必须应用标记。后续 checkpoint 保存集群级标记，策略不依赖
第一个 FE 是否仍在集群中。

初始化失败必须保持关闭访问的状态：

- 首个 FE 日志已经提交：重启回放同一条日志，仍然启用新策略。
- 首个 FE 日志尚未提交：不能把本地 VERSION 文件的存在当成旧集群可以服务的证据。
  当前启动流程在元数据中找不到本节点时拒绝启动；不能绕过这一检查继续提供服务。
- 初始密码格式无效：在写入 ROLE/VERSION 之前失败，修改配置后仍可重新初始化。
- 初始密码应用或持久化失败：启动失败，不能只输出告警后继续服务。

已有集群无论有无 image，只要没有安全初始化标记，均维持旧策略。

不新增日志操作码，可以避免旧版本遇到未知操作码。旧版本忽略 Gson 新字段，并不
保证降级、旧版 checkpoint、再升级之后保留安全策略。实际版本间的元数据兼容性也
受原有版本门槛约束；不承诺任意降级或降级往返保留保护。

## 客户端认证规则

以下规则仅在集群有标记且未开启测试兼容配置时生效。

| 账号状态 | 本机 MySQL | 其他来源 MySQL | HTTP / Stream Load / Thrift / Flight |
|---|---|---|---|
| root 空密码 | 允许进入首次改密会话 | 拒绝 | 拒绝 |
| admin 空密码 | 拒绝 | 拒绝 | 拒绝 |
| root/admin 非空密码 | 按原有认证、锁定与密码策略校验 | 按原有规则校验 | 按原有规则校验 |

规则根据认证时匹配的账号当前密码判断。后来重新设为空密码的账号，在下一次登录时
仍受限制。普通账号的空密码规则不变。

本机只认地址值 `127.0.0.1` 和 IPv6 回环地址，不认整个 `127.0.0.0/8`，也不解析
`localhost` 等主机名。带 PROXY protocol 头的连接不能用于空密码引导或本机免密恢复；
代理头中的来源地址不作为本机身份的证明。运维需要从 FE 自身的网络命名空间直接连接。

本机 TCP 访问仍是运维信任前提，不能证明连接者就是操作员。端口转发、未保留来源地址的
代理和同机其他程序的访问权限，由部署侧控制。

密码拒绝保持 MySQL 错误码 `1045` 和 SQLSTATE `28000`，以兼容部署脚本的凭据回退。
root/admin 使用空凭据失败时，提示如何完成初始化；提示不能取决于服务端是否已设密码。
其他认证方式成功后也必须应用内置账号策略，不能仅覆盖原生密码分支。

## 首次改密会话

会话限制由客户端认证结果设置，不由 `UserIdentity` 或账号密码在 SQL 执行时重新推导。
只允许：

- 给当前账号设置非空密码的 `SET PASSWORD` 或 `ALTER USER ... IDENTIFIED BY`。
- 会话级、常量赋值的 `SET` 以及 `SET NAMES`；不允许 GLOBAL 设置。
- 返回字面量、系统变量或明确允许的连接信息函数的简单 SELECT。
- `SHOW VARIABLES`、ping、quit 和必要的预处理语句生命周期操作。

SELECT 不能只检查外层有没有 FROM。子查询、UDF、文件输出和其他计划/表达式形状默认拒绝。
未绑定的连接信息函数只有在有效 `prefer_udf_over_builtin=false` 时放行，防止同名 UDF 覆盖。
SET 必须逐项校验，防止在一个命令中混入修改其他账号或全局配置的操作。

其他操作返回 `1820`，提示设置非空密码。协议命令层和 SQL 执行层都必须覆盖：
`COM_FIELD_LIST`、`COM_INIT_DB` 等不会统一经过 SQL 执行器。

预处理语句检查其实际保存的计划。`COM_RESET_CONNECTION` 保留首次改密限制；
`COM_CHANGE_USER` 成功认证为其他账号后清理原限制，失败时保留原限制。

密码变更成功持久化后，当前客户端会话立即解除限制。转发给 master 执行的语句，也要
解除客户端所在 follower 的会话限制。其他已经建立的连接不自动获得新的认证结果。
转发结果必须确认成功；master 因密码历史等原因拒绝修改时，follower 保留限制。

## admin 与内部后台任务

admin 空密码时禁止客户端认证，不禁用 admin 身份，也不撤销 ADMIN 角色。
不使用 ACCOUNT_LOCK 实现此规则。

MTMV、INSERT JOB、统计任务等由 FE 直接建立内部执行上下文，使用既有的执行身份和
权限，不进行客户端密码认证。它们默认不携带首次改密状态，因此无需设置 admin 密码
即可正常调度、执行，并在 FE 重启后恢复。

外部定时脚本和调度系统如果使用空密码 admin 连接 MySQL/HTTP，会被拒绝。MTMV 等任务
通过 JDBC catalog 连接回本集群时，该 JDBC 连接仍然需要有效的客户端凭据。

## 配置项与优先级

| 配置 | 默认值 | 用途 |
|---|---|---|
| `initial_root_password` | 空 | 第一次创建集群时设置 root，仍只接受两阶段 SHA-1 哈希 |
| `require_initial_root_password` | false；镜像默认 true | 首次建群必须给 root 初始密码，由 FE 确认是否创建集群 |
| `allow_empty_password_for_root_admin` | false | 测试兼容：允许空密码 root/admin 从客户端正常访问 |
| `skip_localhost_auth_check` | false | 密码恢复：显式跳过本机 MySQL 的 root/admin 密码校验 |

后两个配置不能在线修改，各接收客户端连接的 FE 分别配置。它们用途不同：测试开关不跳过
已有密码的验证，恢复开关不允许远程空密码登录。显式本机恢复优先于空密码限制，但不能
把 PROXY 地址作为恢复依据；其他账号策略保持原有语义。

测试开关在认证时判断，不影响标记写入。删掉该配置并重启后，新集群恢复保护。
当前基线已经将本机免密默认值改为 false，因此保留布尔型，不引入 `auto`，也不将旧集群
的默认值改回 true。

`initial_root_password` 在已初始化集群上被忽略，启动日志说明可以删除该配置。
FE 不读取明文密码环境变量；镜像入口脚本负责读取 secret、计算哈希并写入有效配置。

## Docker、Kubernetes 与工具

官方镜像默认在首次创建集群时需要提供 root 密码或有效的 `initial_root_password`；否则
拒绝启动。测试容器可显式设置 `DORIS_ALLOW_EMPTY_PASSWORD=true`，或者在有效 FE 配置中
明确设置 `allow_empty_password_for_root_admin=true`。已有元数据的节点
重启和新增 FE 加入既有集群，不重新初始化账号。

K8S 云 FE 可能在启动 JVM 后才从 MS 发现远端 helper；没有本地 VERSION 或 CLI helper
不代表创建新集群。镜像入口通过非敏感的 `DORIS_REQUIRE_INITIAL_ROOT_PASSWORD=true`
设置该配置的启动默认值并准备已有凭据，无须为此修改只读 ConfigMap。配置文件可覆盖默认值。
由 FE 在确认创建首个 ROLE/VERSION 前检查密码要求。加入已有集群或已有本地元数据时
不执行该检查；显式测试兼容仍允许空密码初始化。这个配置只控制初始化，不改变登录规则。

入口脚本支持 `DORIS_ROOT_PASSWORD_FILE`，也支持显式提供 `DORIS_ROOT_PASSWORD`。
root 类型的已有 basic-auth secret 可以复用；非 root 的节点管理账号凭据不能被当成
root 初始密码。所有节点探测和注册连接使用各自配置的凭据。

secret 不作为命令行密码打印或记录，不写入集群描述；初始化配置仅保存哈希。
密码文件的各读取端仅去掉末尾 LF，不转换 CR 或文件内部换行。
配置判断必须考虑 `fe_custom.conf` 对 `fe.conf` 的覆盖以及实际 `meta_dir`。

doris-compose 支持 `--root-password-file`，集群描述只保存文件路径和初始化哈希，连接
时从该文件读取密码。回归框架 HTTP 请求使用配置的 HTTP 凭据，root 连接也使用已提供
的 root 凭据；当 JDBC 和 HTTP 都使用其他账号时，可用 `rootPasswordFile` 单独提供 root 凭据。
CI 和普通 Docker 回归套件显式开启测试兼容；验证安全规则的套件关闭它。

仓库外的 operator、管理工具、快速上手文档和本地部署配置需要在发布时同步调整，不能
继续假设新集群的 root/admin 可以通过空密码远程登录。

## 提示与日志

root 给自己设置密码成功时，如 admin 仍为空密码，OK 包说明 admin 的实际可用状态，
并提示按需执行 `ALTER USER 'admin' IDENTIFIED BY '...'`。

启动后根据已经回放完成的元数据输出：旧策略下的空密码账号以及显式开启的不安全配置
产生 SECURITY WARNING；新策略下 root 等待本机引导产生告警；admin 空密码且不能
客户端登录时只输出说明信息。配置和密码日志不能包含明文或哈希值。

## 必须覆盖的验收场景

- 新集群、旧 image、无 image 仅 journal 的旧集群，以及标记的 image/journal 回放。
- 在首个 FE 日志提交前后中断初始化，确认不会以旧策略继续服务。
- root/admin 的入口、地址、密码状态、测试兼容与恢复开关组合。
- 原生密码认证及认证成功后的统一内置账号策略，包括证书认证；错误码和错误提示的一致性。
  HTTP 保持已有接口的拒绝格式，例如 REST JSON 的 `code=401`，不统一改写传输层状态。
- SQL 子查询、UDF、OUTFILE、混合 SET、协议命令、预处理、多语句、reset/change-user。
- 本机 IPv4/IPv6 的真实客户端首次改密，以及连接 follower 改密后的限制解除。
- 无测试兼容、root 有密码、admin 空密码时，定时 JOB、MTMV 刷新和统计任务正常；FE 重启
  后后台任务继续运行。容器内执行 mysql 或共享 FE 网络命名空间可用于本机端到端测试。
- 镜像缺少初始凭据时拒绝创建新集群；已有集群升级和新增成员不重新设密码。
- group commit 与集群 token 审计导入不受客户端密码限制影响。
- 具体受支持版本间的旧二进制回放检查；不能只用新版兼容性检查模式代替真实版本验证。
