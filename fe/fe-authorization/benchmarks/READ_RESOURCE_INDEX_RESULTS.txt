Baseline: frozen pre-index Doris plugins from 65db4e385fd (descriptor sharing
and negative parent-scope summary). Indexed: Boolean controller path at a536d851c95.
These historical measurements predate the subsequent Unicode and dynamic-resource correctness guards;
they are not a fresh benchmark of that revision. Current correctness validation
is recorded separately in READ_RESOURCE_INDEX_CORRECTNESS.txt.
All variants share unmodified Ranger 2.9.0 and matching dependencies.
Host/JVM: shared Intel Xeon Platinum 8369B host, 16 logical CPUs, no CPU pinning;
Oracle JDK 17.0.10, G1, -Xms256m -Xmx12g. No other task builds/tests overlapped
this formal serial matrix; unrelated workloads on the host were not controlled.

Model: 5000 physical tables, one SELECT policy per user, 800 separate OR blocks
per user, plus one global ADMIN policy for a separate bootstrap administrator.
Each employee block has three real columns and the user-named AD fake column.
20 warmups and 120 samples, seed83, half allowed and half denied.
Each variant uses its own JVM. Installation and a full replacement refresh are
included in heap observations; request percentiles exclude installation.
No login, SQL planning/execution, HTTP download or audit sink is measured.
User-store group lookup/context enrichers are disabled in this isolated model.

scope: prior Doris ADMIN OR SELECT cascade with impossible parents omitted.
sr: native per-column SELECT call pattern using identical DORIS service data;
    this is NOT a StarRocks FE, service-definition or SQL performance result.
indexed: same Doris Boolean checks, using table/user/native-matcher references.
Result comparison covers final request verdicts. Raw Ranger API metadata is
unchanged and covered by the separate audit/native regression suites.

Correctness and practical limits
- All final request fingerprints agree across the three variants at every size.
- Each run verifies revocation of an old table and access to a newly granted one.
- Native calls count policy-engine API entries; indexed queries still execute
  the original Ranger column resource matcher for their relevant blocks.
- The raw Ranger API, audit callbacks and complex policy paths remain native.
- Services with unsupported enabled policies use fallback;
  a default group policy can disable the fast path for the complete service.
- Native policy/evaluator/index memory is retained. Added steady index memory
  does not represent the FE heap requirement or the policy refresh peak.
- In the 3000-user run, observed refresh peak was 8134.26 MiB for scope and
  9207.41 MiB for indexed. Installation/refresh are not claimed to improve.
  Peaks include generation/install/validation/explicit GC, sampled every 5 ms;
  they depend on GC/heap dynamics and are not a safe capacity bound.
- This is one short serial batch on a shared host. No end-to-end SQL, concurrent
  client capacity or refresh-time query-tail SLA follows from these numbers.
- The benchmark builds request/result wrapper objects to model the controller;
  production indexed Boolean decisions return before creating a raw request.
- Small policy sets may see little benefit or extra lookup overhead.
- Ranger 2.8 compatibility smoke passed with identical verdict fingerprints;
  this is not a tested source backport or an older-FE binary replacement.
